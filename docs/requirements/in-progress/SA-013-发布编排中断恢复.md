# SA-013 发布编排中断恢复

## 背景与本轮范围

2026-10-05 设计启动时，编排在外部 Git 操作结束后才保存 Run；传输超时和数据库提交失败可能留下无法从 Run 判断的外部结果。设计时 Run ID 使用毫秒时间戳，RunItem ID 没有 Run 作用域；S1 已修复新记录的身份隔离。

设计和 S1 已交付：身份隔离、幂等受理及持久预览已实现，不执行 Git 副作用，不迁移历史 Run。此前交付与 SA-018 已随 `5d85b17` 提交并推送。2026-10-08 S2 获批并完成操作证据、仓库写入保护、只读核对及隔离验证。2026-11-21 用户已授权持续研发、必要重构、分组提交与分阶段推送；S3-A/B1、S3-B2、S3-C1、S3-C2-A 已分阶段推送并验收，当前唯一队首为尚未实现的 S3-C2-B1「无 operation 的过期 RUNNING 接管」；后续范围和未验收能力仍逐切片追踪。

## 目标

- 外部写入前，计划、任务和操作意图已经持久化且可查询。
- 明确区分确认失败、确认成功、结果未知；未知结果不得盲目重试。
- Run / Item / Attempt 标识不碰撞；重复请求不重复创建计划，历史记录不被后续运行覆盖。
- 进程重启、任务租约失效或数据库故障后，先核对外部证据，再决定恢复或人工复核。
- 同一仓库的系统内写操作互斥；旧执行入口必须纳入写入边界，不能绕过恢复协议。
- 界面、API、导出、审计和备份恢复消费同一事实；不保留旧写路径或并行执行协议。

## 验收标准

- [x] C1 窗口新执行协议在任何 Git 写入前可查询计划和任务；版本与收尾的同等任务化仍在 S4。
- [x] S1 预览受理同键同请求返回同一 Run，改变请求内容返回冲突。
- [x] 同毫秒并发运行及跨 Run 重试不覆盖历史执行项。
- [ ] 请求发出后丢失响应、成功后落库失败、重启接管时先进入 UNKNOWN 并复核。
- [ ] 没有足够证据时阻断后续写入并进入人工复核，不宣称执行成功或自动回滚 Git。
- [ ] 同仓库并发及过期 worker 不得绕过写入门禁。
- [x] 默认 MANUAL：Publish 不隐式产生执行意图，已删除自动发布监听器。
- [x] C2-A 显式 Orchestrate 的持久任务与受理同事务；默认数据库扫描不依赖唤醒，重启继续原 PENDING，MR 成功前缀不重放。
- [ ] 页面展示受理、执行、结果未知、待复核及恢复记录；历史 Run 不自动重放。
