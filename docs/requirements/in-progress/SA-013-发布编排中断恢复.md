# SA-013 发布编排中断恢复

## 背景与本轮范围

2026-10-05 设计启动时，编排在外部 Git 操作结束后才保存 Run；传输超时和数据库提交失败可能留下无法从 Run 判断的外部结果。设计时 Run ID 使用毫秒时间戳，RunItem ID 没有 Run 作用域；S1 已修复新记录的身份隔离。

设计和 S1 已交付：身份隔离、幂等受理及持久预览已实现，不执行 Git 副作用，不迁移历史 Run。此前交付与 SA-018 已随 `5d85b17` 提交并推送。2026-10-08 S2 获批并完成操作证据、仓库写入保护、只读核对及隔离验证。2026-11-21 用户已授权持续研发、必要重构、分组提交与分阶段推送；S3-A/B1、S3-B2、S3-C1、S3-C2-A、S3-C2-B1 已分阶段推送并验收。B1 后端 `3f810c8` 与文档 `5441df6` 已推送，固定 SHA 的 Full-Link44911634004为5/5；当前唯一队首为 S3-C2-B2「建分支成功证明与 APPLIED 结果投影恢复」，实现与最终本地门禁已完成，定向189/API48/普通700与静态224714同一稳定树通过，提交/推送及本片固定SHA CI待完成；后续范围和未验收能力仍逐切片追踪。

## 目标

- 外部写入前，计划、任务和操作意图已经持久化且可查询。
- 明确区分确认失败、确认成功、结果未知；未知结果不得盲目重试。
- Run / Item / Attempt 标识不碰撞；重复请求不重复创建计划，历史记录不被后续运行覆盖。
- 进程重启、任务租约失效或数据库故障后，先核对外部证据，再决定恢复或人工复核。
- 同一仓库的系统内写操作互斥；旧执行入口必须纳入写入边界，不能绕过恢复协议。
- 界面、API、导出、审计和备份恢复消费同一事实；不保留旧写路径或并行执行协议。
