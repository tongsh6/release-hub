# S1 实施口径

用户已批准 S1。该切片修复新 Run/Item 的身份隔离，并新增持久计划预览，不启用 worker、不调用 Git、不改写历史记录。

- 新 ID 使用 UUID，旧字符串 ID 的读取不变，retry 来源继续由 metadata 保存。
- 预览写入真实 Run（executionVersion=2、状态 PLANNED）及关联的不可变 `run_plan` 快照；已有 Run 不回填，不新增实际运行任务。
- 快照明确为 LOCAL_ONLY，记录本次读取并校验的本地范围、顺序、分支和版本；不声称远端引用已核实。后续执行需另建带来源的新计划，不能把预览直接激活或改写。
- 请求仅由窗口 ID、规范化仓库/迭代集合及 failFast 决定指纹；同主体与幂等键的重复请求先查原快照，再读取当前业务状态。
- PostgreSQL 事务内幂等锁加唯一约束串行化同一 key；Run 与快照同事务提交。预览不包含 Token 或 clone URL。
- 新接口为 `POST/GET /release-windows/{id}/run-plans` 和 `GET /runs/{id}/plan`；窗口列表返回最近 20 条预览摘要，任意已知 Run ID 可重新查询。
- API 与页面明确预览不可执行。旧 retry 入口拒绝 executionVersion=2 的预览 Run。
- 计划最多 1000 个执行项，超过时提示缩小选择范围；仅封存经过当前应用不变量校验的数据，不把它当成执行前检查。
- S2 以后才处理 Git 证据、任务调度、恢复与补偿；S1 不承诺完整发布可恢复。
