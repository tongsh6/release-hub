# 首次生产部署必须单独验证账户与数据库卷

## 本次发现

- `prd` 关闭开发 seed 后，原本没有创建可登录账户的路径；使用 `admin/admin` seed 的认证测试无法发现这个问题。
- 使用独立 PostgreSQL 空库、真实 `prd,real` 配置和 Flyway 完成复现，登录由 401 修复为 200。后续不要用测试 profile 的固定管理员代替首次生产部署验收。
- 首次账户初始化需要把“用户表为空”和“创建账户”放入同一事务锁内。已有任意用户即跳过，在检查空表之后才校验初始凭据，才能在移除初始密码后安全重启。
- PostgreSQL 18.1 镜像的持久卷应挂载到 `/var/lib/postgresql`；旧 `/var/lib/postgresql/data` 挂载会令空库启动失败。验收须包括重建容器后的数据保留。
- Flyway 对 PostgreSQL 18.1 有超出已测试支持范围的警告。本轮 33 项迁移成功不代表全部功能已验证，也不构成自行升级依赖的理由。

## 边界

首次初始化不是密码重置接口。不要清空用户表或开启固定密码 seed 来修复生产登录。已有数据库卷应先备份并在独立卷演练恢复，不能直接套用新挂载点当作跨主版本升级。
