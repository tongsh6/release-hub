# 生产 Token 加密与恢复边界

## 经验

- 加密类存在不代表部署已加密。必须用真实生产 profile 保存凭据，再直接检查数据库原始值。
- AES round-trip 只能证明当前密钥可用于加解密，不能证明它匹配历史数据库。启动时必须另外校验有格式标识的存量密文。
- 带 `enc:v1:` 标识的值解密失败时必须报错，不能原样作为 Token 返回；无标识旧数据则需要明确兼容与迁移边界。
- 数据库备份不能替代密钥备份。恢复验证应将 SQL 导入另一空库，沿用原密钥，最后验证真实适配器发出的凭据请求。
- 启动校验只读取凭据并报告数量，不打印内容、不自动迁移；密钥轮换与旧数据迁移不是默认配置修复的附带动作。
- SQL 恢复使用 `ON_ERROR_STOP=1`，避免导入失败后继续启动应用。
