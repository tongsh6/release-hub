# 首次部署管理员初始化修复

## 目标与授权

用户在项目评估和下一步建议后要求“开工”，本次先修复全新部署无法登录的问题，并将其调整为 SA-017 队首。属于恢复部署文档承诺行为的 Bug 修复；不新增公开注册 API，不改变认证协议，不扩大到 RBAC。

最终行为：生产启动时，在用户表为空的情况下使用部署者显式提供的用户名和密码创建首次账户，随后可通过现有登录页登录。已有任意用户时不创建账户、不重置密码；凭据缺失或不合格时空库启动失败，错误信息不包含密码。

## 完整范围与模块边界

- Domain：复用 User，不引入角色或新的数据库表。
- Application：首次账户初始化用例、凭据约束和事务边界；复用 PasswordPort。
- Infrastructure：启动入口、配置读取、用户表初始化锁和持久化；数据库并发控制不能放到应用层 SQL 中。
- Bootstrap / Compose：生产配置开启初始化检查，部署者通过环境变量提供凭据；开发 seed 保持现有行为。
- API / Frontend：复用现有登录接口和登录页，不增加未认证管理入口。
- 审计：只记录创建或跳过结果，不打印密码、密码哈希和完整配置对象。
- 测试：先复现 seed 关闭下无法登录，再验证空库创建、非法凭据、重启不覆盖、已有非同名账户、并发初始化以及认证访问。
- 文档：首次部署、凭据移除、重启和失败排查说明；同步路线图、场景矩阵和台账。

## 切片与依赖

1. 复现：使用独立 PostgreSQL 空数据库和生产 profile，关闭 seed，验证配置凭据后仍无法登录（RED）。
2. 修复：应用用例 → 持久化锁 → 启动配置 → Compose，覆盖启动到登录的完整路径（GREEN）。
3. 交付：回归、静态扫描、部署说明和证据记录。

每个切片都服务于“新部署可安全登录”，不混入 GitLab、发布业务或历史数据迁移；部署配置及新增初始化代码可以一并回退，已创建账户不自动删除。

## 风险与回滚

- 初始化仅在空用户表写入；不连接或修改现有业务数据库与 GitLab。
- PostgreSQL 事务内锁定用户表，将空表判断与创建放入同一事务，避免多实例竞争。
- 凭据经环境传入，首次成功后应从部署配置移除并重建后端容器；不把初始化当作密码重置工具。
- 生产启动缺失必要凭据会失败，而不会返回一个无法登录的健康服务。
- 本次不调整生产 Git Token 加密、pnpm/CI、发布编排恢复；这些仍是后续工作。
